# 독립 평가자 표준 절차 (2026-11-08)

PM이 평가자를 시작할 때 이 문서를 따르게 하고, 프롬프트에는 회차·대상 sha·이번에 중점 볼 것만 적는다.

## 공통
1. 평가자는 만든 세션이 아니다. 코드·데이터·문서를 고치지 않고 커밋하지 않는다. 결과는 `evaluation/runs/<날짜>-r<회차>-<ac|b|de>.md`(+ A·C는 `-queries.json`)에 단계마다 이어 쓴다.
2. 대상 확인: `git ls-remote origin main`으로 최신 sha를 확인하고(이 클론은 main만 추적해 fetch가 오래된 커밋을 줄 수 있다) `git fetch origin main` 뒤 `git worktree add /tmp/eval<회차><영역> <sha>`에서 작업한다. 공유 작업 폴더는 건드리지 않는다. 공개 사이트가 아니라 이 sha의 로컬 서버(`python3 -m http.server`)로 측정하고 라이브 주요 파일 md5를 대조한다.
3. 기준은 `evaluation/rubric.md`(항목별 단계, 보충 규칙 전부)와 직전 회차 run 문서. 항목마다 근거(화면 주소, 수치, 질문 번호)를 적고, 모든 합산 규칙을 계산해 하나로 보고한다. 평가자 재량 규칙은 만들지 않는다.
4. 범위는 약 45분. 컨테이너가 재시작될 수 있으니 단계마다 파일에 쓴다. 측정 한계(환경, 동시 실행, 1회 측정)는 숨기지 않고 적는다.
5. 마지막 보고: 항목 점수, 큰 결함(파일·행·쪽 위치 포함), 직전 회차 대비 변화, 같은 항목이 연속 오르지 않은 이유.

## A·C (과업·정보 충분성)
- 과업 12건 중 6건은 `evaluation/fixed-tasks.md`의 고정 묶음(문구 변경 금지, 정답은 회차마다 재확인), 6건(쉬움 3·어려움 3)은 **새로 구성**한다. 검색 질의 약 200개도 **새로 구성**한다. `evaluation/runs/*queries.json`·`tools/pm/searchgold.json` 전체와 공백 제거 후 겹침 0, 분류(학교·고입·용어·약칭·숫자·날짜·수능·대입·문장형·자료 없음)와 비중은 직전과 같게. 질의는 결과를 보기 전에 쓰고 결과를 보고 바꾸지 않는다.
- 390px 터치 Playwright로 수행한다. 메뉴 경로(좌측 트리·서랍·하단 바·홈)로 푸는 보조 지표(클릭 수·헤맴)를 따로 적는다.
- 검색 점수는 '검색 적중 정의'(rubric)대로: 자료 있는 질의 적중률과 자료 없는 질의 정직 안내율을 따로 적는다. 자동 판정 후 전수 재검토하고 수정 내역을 JSON `manual`에 남긴다.
- 질문 은행 47문을 새 표현으로 물어 화면에 답이 있는지(C1)를 본다. 제외 질문은 `excluded-by-data.md`.

## B (정확성·신뢰)
- 표본은 직전 회차들과 겹치지 않게 새로 약 80~100건. 먼저 직전 회차 이후 `portal/data`·화면 문구를 바꾼 PR(git log)이 만든 주장 전부를 원문과 독립 대조한다(새로 손댄 영역에서 오류가 잘 난다). 그다음 직전 run의 '미검증 영역 지도'에서 낮은 영역을 본다.
- 값 오류뿐 아니라 '화면이 말한 것과 실제가 다른 신뢰 결함'(메뉴 설명 줄, '없음' 선언, 안내문, 기준 시점 누락)도 오류로 센다. 원문 위치는 인쇄쪽/PDF쪽을 구분해 적는다.
- B2는 데이터 필드와 자료실 '출처·확인일' 기준(rubric '출처 표기 기준 변경'), 화면 표시 여부는 B1에서.
- 접근이 막힌 원문(세션 필요·캡차)은 우회하지 않고 '확인불가'로 적는다.

## D·E (디자인·기술)
- 직전 평가 커밋과 로컬 서버 2개로 같은 환경에서 상대 비교한다(Lighthouse 절대 점수는 샌드박스 영향으로 비교하지 않는다).
- 항목: 창 폭별(1440·1024·900·899·390·360·320) 가로 스크롤·겹침, ?hl= 40링크의 도착·60px+ 이동, CLS(각 20회), 인쇄 복원, 용어 풀이 창, 터치 영역, 글자 크기, 홈 390 높이(2,500px), 다크·스킨, 서랍·키보드·aria, 도구 묶음(`WORKFLOW.md`). 이번 회차에 바뀐 화면은 스크린샷 육안 비교를 더한다.
- '할머니 관점' 남은 5건을 직전과 비교해 적는다.

## 결함 구분 (2026-11-09)
- 모든 결함을 '중대/소프트'로 구분해 적는다(정의: rubric 2026-11-09 갱신). B1 단계는 중대 결함 건수로, 소프트가 3건 이상이면 한 단계 감점. 소프트도 목록으로 남긴다. 구분이 애매하면 근거와 함께 중대로 적고 PM이 최종 구분한다.
