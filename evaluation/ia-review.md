# 메뉴 구조(정보구조) 독립 검수

- 검수일 2026-11-06, 기준 `origin/main` 22b292c(PR #498). 만든 세션이 아닌 독립 검수. 코드·화면을 읽고 Playwright(390px)로 실제 화면을 열어 확인한 것만 사실로 적었고, 판단·추정은 "판단"으로 표시했다.
- `temp/menu`는 이 브랜치에 없어 보지 않았다(참고 자료에 끌리지 않음).
- 범위: 구조·이름만. 새 기능은 만들지 않는다. 사람 이름 없음, 포인트색은 #C4310D 하나, 메뉴 2단계, "확정" 표시 없음.

## 0. 결론 (먼저)

1. 지금 길찾기 장치가 **7겹**이다: 하단/상단 탭 5개 + 안쪽 가로 메뉴 줄 + 헤더 `보관함` + 화면 안 윗줄 탭(일정 4개, 대입 규칙 3개) + 화면 안 `요약|상세` 토글 + 홈의 단계 허브(링크 18개) + 접이식 안의 접이식. 할머니가 "가지"를 따라가기 어렵다.
2. 같은 곳을 가리키는 이름이 흩어져 있다. 예: `#select/curriculum?v=middle` 하나에 홈이 "중학교 배정 준비", "중학교 배정 절차·일정", "교과서·교과 구성", "교과서", 메뉴가 "중학교 배정"이라는 5개 이름을 붙였다.
3. 질문 은행 기반 과업 44개를 **라벨만 보고** 시험한 결과 현재 성공 43%, 헤맴 52%, 실패 5%. 단계 축 개편(A)은 93%, 과업 축 개편(B)은 79%(판단, 아래 한계 참조).
4. **추천: A 단계 축.** 최상위 6개(중학교 입학 / 고등학교 입학 / 고교 생활 / 대학 입시 / 일정 / 자료·소식) + 홈. 좌측 고정 트리 사이드바(데스크톱) · 메뉴 서랍(모바일), 트리는 항상 펼쳐 둔다.
5. 새 기능 없이 가능한 구조 변경 4가지: `고교 유형·전형`을 접이식에서 독립 항목으로, `학교 비교`와 `과목 비교(상세)`를 메뉴에 분리, `중학교 비교·입학 준비`를 배정 화면의 접이식에서 메뉴 항목으로(열림 상태 앵커), `중학교 생활`(빈 안내 화면)을 폐지.

**한계(중요)**: 아래 트리 시험은 라벨 해석을 검수자 한 사람이 판단한 것이고, 개편안도 같은 사람이 짰으므로 개편 쪽 점수가 낙관적이다. 확정 전에 가족 3~5명에게 실제 라벨 시험(종이로 과업 10개)을 권한다.

| 보관함 | 자료·소식 | 보관함이 무엇인지 모름 |
| 바로가기 | 관련 사이트 | 어디로? |
| 업데이트 기록 + 출처 목록 | 출처·확인일 | 비슷한 두 항목을 합침 |
| 편제표(제목) | 과목표 | 전문용어 |

합칠 것: (1) `출처 목록`+`업데이트 기록` 한 화면 두 구역 (2) `대입 규칙`의 윗줄 탭 `바뀐 소식`을 `자료·소식 > 바뀐 소식`으로 흡수(리다이렉트) (3) `중학교 생활`(빈 화면)을 폐지하고 `입학 준비`로 (4) 일정의 `학년별` 탭 하나만 남기고 고등학교 메뉴의 `학년별 로드맵` 항목 제거 (5) 구 MENU 상단의 죽은 정의 삭제(menu.js는 TREE 하나만).

쪼갤 것:
- 학교 비교 화면(`?v=hs`): ① 고교 종류(유형 패널 전체) ② 학교 비교(4개교 한눈에 + 31교 표) ③ 설명회 노트 ④ 편제표 요약(4개교)은 `학교 비교` 아래 구역으로 두고 상세 필터는 `과목 비교`(`?v=compare`)로. 기존 `요약|상세` 토글은 두 메뉴 항목이 대신하므로 숨김 가능. 같은 데이터 모듈이라 화면 코드 이동 없이 "어느 구역을 처음 보여 줄지"만 정한다.
- 중학교 배정 화면(`?v=middle`): `배정 안내`(원칙·일정·근거리), `중학교 비교`(접이식 `mid-cmpd`를 열어 둠), `입학 준비`(접이식 가이드를 열어 둠)는 같은 화면의 열린 구역을 앵커로 구분한다(새 파라미터 `open=cmp|guide`는 "열림 상태"이고 기능이 아니다; 구현이 부담이면 처음에는 항목만 나누고 `#...` 앵커로 스크롤).
- 학교 지도: 중학교 지도·고등학교 지도를 각 단계 가지에 둔다(현재도 해시가 `lv=middle`로 갈라져 있음).
- `일정` 윗줄 탭 이름: `고입→고교 입학`, `대입→대학 입시`, `졸업·입학`, `학년별`. `?t=` 키는 그대로.

## 7. 구현 순서 제안 (각 단계가 독립 배포 가능)

1. (소) 라벨만 바꾸기: 위 이름 바꿈 표, 대입 > 입시 일정 하이라이트 오류, 시스템 `t=types` 화면 제목 수정. 해시 변경 없음.
2. (중) 메뉴 데이터를 `TREE` 한 벌로 통일(구 `MENU` 삭제), 사이드바·서랍 렌더. 안쪽 가로 메뉴(`.subnav`) 제거, 보관함 헤더 링크를 `자료·소식` 가지로 흡수.
3. (중) 접이식 → 항목 승격: 고교 종류, 중학교 비교, 입학 준비(열림 앵커), 설명회 노트(`bf=1`), 학교 비교/과목 비교 분리.
4. (소) 폐지·합치기: `중학교 생활`, 대입 규칙의 윗줄 탭 `바뀐 소식`, `출처 목록`+`업데이트 기록`, 로드맵 중복 문.
5. (소) 홈 허브·안내·`dash.js` HUBS의 링크 라벨을 메뉴 라벨과 같게(예: `v=middle` 이름 5개 → `배정 안내`).
6. 가족 3~5명 종이 라벨 시험 10과업 → 이름 조정.

모바일: 하단 바는 `메뉴 | 오늘 | 일정 | 검색` 4칸을 권한다(판단). 서랍 안 트리는 항상 펼침, 닫는 곳은 바깥 터치. 서랍 열기 1회가 추가되지만 `오늘`·`일정`은 여전히 1탭이다.

## 8. 위험·확인할 점

- 접이식을 항목으로 올리는 3단계는 화면 코드의 `open` 앵커 처리가 필요하다(상태 파라미터 하나, 기능 추가는 아님). 불가하면 항목을 나누지 말고 화면 맨 위에 한 줄 목차(앵커 링크)로 대체.
- `고교 생활`은 현재 항목이 2개뿐이라 가지가 빈약해 보일 수 있다. `학년별 체크리스트` 등이 열리면 채워진다. 대안: `고교 생활`을 `고등학교 입학`에 합쳐 최상위를 5개로(항목 8개가 되어 길어짐). 권장은 분리 유지.
- 사이드바에 같은 화면이 두 번(예: 일정) 나온다. 단계 축에서 날짜를 찾는 과업(T02·T16·T35)을 살리려는 의도적 중복이며, 강조는 같은 해시를 모두 켠다.
- 라벨 시험은 검수자 1인의 판단이다(0장 한계 참조).
- 사용자 결정과 충돌 없음: 사람 이름·프로필 없음, 포인트색 변경 없음, 메뉴 2단계, `확정` 표시 없음, 새 기능 없음. 단 `메뉴는 단순하게(하위 메뉴 증가 싫음)` 지침과 관련해, 항목 수는 현재 안쪽 메뉴 11 + 보관함 5 = 16개에서 **트리 28줄(최상위 6 + 하위 22, 그중 단계별 `일정` 3줄은 같은 화면의 두 번째 문)**로 늘지만, 접이식·윗줄 탭·토글 3종이 사라진다. 항목 수보다 "숨은 길" 수가 줄어드는 교환이다. 항목 수를 늘리고 싶지 않다면 `입학 준비`·`설명회 노트`·`과목 비교`를 하위 항목 대신 학교 비교/배정 안내 화면 위 목차로 두는 축소안(하위 19개)이 있다.
