# 06 휴리스틱 검토: 화면 개선 계획 초안

근거(2차 자료, NN/g 원문은 검색에 안 잡혀 미확인): Nielsen 10원칙 [uxdesign.cc](https://uxdesign.cc/the-practicality-of-neilsons-10-91cd4a6fb61c), [CIRCA](https://circa.cs.ualberta.ca/index.php/CIRCA:10_Usability_Heuristics_-_Nielson,_Jakob). Hick 법칙·점진적 공개(공개 깊이 2~3단, 숨김 위험) [uxcel](https://uxcel.com/blog/hicks-law-in-ux-design-simplifying-choices-for-faster-decisions), [concepts](https://concepts.dsebastien.net/concept/progressive-disclosure/). 대시보드는 요약 우선·드릴다운, 한 화면 30개 이상 지표는 과부하 [easy.bi](https://easy.bi/blog/dashboard-ux-optimization). 그 사이트의 "20~40% 개선"은 출처 없어 쓰지 않음.

## 1. 휴리스틱별 위험과 보완
1 상태 가시성: 상태줄을 한 줄로 압축하면 보도/추정/기준연도가 잘림 -> 줄바꿈 허용, 추정은 항상 표시.
2 현실 일치: 허브 띠 "숫자 1"이 무슨 수인지 모호 -> 단위 병기("D-12", "3건"), 중입/고입 용어는 첫 등장 풀이.
3 통제·자유: 허브 접힘·필터 접기 상태가 새로고침에 사라지면 곤란 -> 접힘 기억, 되돌리기 가능.
4 일관성: 패널 5종·각도 차등이 같은 개념을 다르게 보이게 함 -> 각도는 장식 요소에만, 동작·위치는 고정.
5 오류 예방: 부족 경고가 틀리면(수능 범위 추정) 잘못된 과목 선택 유도 -> 경고에 상태·출처 필수.
6 인식>회상: 검색 /키, 허브 접힘은 회상 의존 -> 보이는 돋보기·"자주 찾는 곳" 노출.
7 효율성: 좋음(검색, 1클릭 연결). 초보용 경로와 숙련용 단축을 분리.
8 미니멀: 핵심 위험. 18~24개는 이 원칙과 정면 충돌(아래 2, 4).
9 오류 복구: 0건 검색 대안은 있으나 데이터 없음("준비 중") 화면 규칙이 없음 -> 추가.
10 도움말: 계획에 없음 -> 용어 ⓘ를 신규 패널에도 적용.

## 2. 수치 기준 타당성
- 첫 화면 18~24단위: 과다. 사람 작업기억·Hick 관점에서 첫 화면 최상위 묶음(그룹)은 7±2, 단위는 12~16 권장. 18~24는 "스크롤 포함 첫 2화면"로 완화하고, 지표는 "개수"보다 "묶음 수 7 이하 + 학부모 5초 과업 성공"으로.
- 일정 40px 행: 데스크톱 OK, 모바일 터치는 44px 이상이라 모순 -> 모바일 48px, 보조 정보는 2줄.
- 홈 모바일 3,000px: 타당하나 접힘으로 달성하면 발견성 손실 -> 3,500px, 단 첫 3스크린에 핵심 과업.
- 빈 영역 25% 이하: 여백은 위계의 수단. 15~30%를 허용범위로, 측정 대신 시선 군집 검수.
- 간격 4/8/12/16/24/40, 본문 15/16px: 적절. 12px 보조 글자는 학부모(40~50대)에겐 작음 -> 13px 이상.
- 점진적 공개 깊이: 2단 이하 지키기(자료상 2~3).

## 3. 누락
- 사용자 세그먼트 분리 없음: 학부모 vs 중3 vs 초6의 과업이 다르나 홈이 하나. 화면에 사람 구분을 넣지 않는다는 결정과 충돌하므로 "단계별 허브"로만 해결.
- 현재 단계 판정 기준 부재: 기본값=날짜(학년도 3월 기준 자동), 사용자가 고정 가능하게. 자동 크기 변화는 매번 레이아웃이 달라져 일관성(H4)을 해침 -> 크기 차등 대신 순서/강조선만.
- 접근성: 스크린리더, 키보드 포커스, 반투명 대체 외 색맹. 인쇄·공유(학부모 간 전달) 과업.
- 회귀 위험: 기존 URL(?v=compare)·북마크, 사진/D-day 로컬 저장 데이터 유지, 다크모드.
- 성능: 블러 8px 다수 패널은 저사양 모바일에서 끊김 -> 패널당 아닌 컨테이너 단위, 모바일은 불투명.
- 데이터 신선도: 정보 2배 증가 시 갱신 책임·오류 정정 흐름.
- 사용자 결정(이름·프로필 미표시, 메뉴 단순)과 "사이트맵 홈 + 허브 5개"의 중복 메뉴 위험.

## 4. 반대 의견
정보를 늘리면 해로운 경우: (a) 학부모가 "이번 주 할 일"을 찾는 5초 과업에서 신호 대 잡음비 하락, (b) 추정 정보가 눈에 많이 띄면 확정으로 오해해 잘못된 결정 유도, (c) 모바일에서 작은 글자·밀집 터치로 오류 증가, (d) 갱신 못 한 정보가 늘면 신뢰 하락, (e) 위계 없이 균일하게 촘촘하면 시선이 흩어짐. 공백 제거보다 "공백의 용도 전환"이 안전. 반투명 장식은 가독성에 이득이 없어 핵심 숫자·표 위에는 불투명.

## 5. 수정 우선순위
1. 측정 기준 재정의(과업 성공·5초 테스트, 묶음 7 이하)와 기준선 확보 (A 이전).
2. 고교 입학 요약 우선 + 탭 2겹 + 모바일 비교(심각도 3, 확실한 이득).
3. 대학 요건 -> 계획표 연결(핵심 과업, 심각도 3).
4. 일정 "이번 주" + 행 밀도(모바일 48px).
5. 홈 재배치: 현재 단계 판정 규칙 확정 후, 크기 차등은 최소화, 반투명은 마지막.
6. 중학교·대입 2~3단, 전역 정리, 접근성·성능 QA.
한 번에 홈 전체를 바꾸지 말고 단계마다 사용성 시나리오 5개로 회귀 확인. 손글씨는 제목·D-day 숫자만 유지.
