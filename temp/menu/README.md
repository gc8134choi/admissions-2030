# 메뉴 개편 시안 (temp/menu/A · B · C)

요청: 하단 탭 5개 + 헤더 링크(보관함) + 화면 안 글자 탭([입학|생활], 일정 필터)으로 흩어진 메뉴를 **한 군데·최대 2단계·최상위 5개**로 모으고, 정보성 화면 읽기 레이아웃을 함께 개선한다.
시안은 실제 portal CSS(`style/theme/scrap`)와 스크랩북 디자인(포인트색 #C4310D 하나, 사람 이름·프로필 없음)으로 만든 정적 HTML이며 데이터 연결은 없다(날짜·숫자는 `policy.json` 값 그대로).
다시 만들기: `python3 temp/menu/build.py` (HTML), `node temp/menu/shoot.js` (스크린샷, 서버 `python3 -m http.server 8000` 필요).
열어 보기: `temp/menu/A/index.html`, `B/index.html`, `C/index.html` (+ 같은 폴더의 `credit.html` 학점제, `system.html` 수능·내신, `middle.html` 중학교 배정).
스크린샷: `temp/menu/shots/{A,B,C}-{index,credit,system,middle}-{m,d}.png` (m=390px, d=1440px), 서랍 열린 모습 `A-drawer-m.png`, `C-drawer-m.png`.

## 공통 메뉴 트리 (3안 모두 같은 이름·순서, 2단계)
쉬운 말·한 항목 8자 안팎. 괄호는 **지금 이름**과 **그대로 유지되는 주소(해시)**.

| 1단계 | 2단계 (새 이름 ← 지금 이름) | 주소(변경 없음) |
|---|---|---|
| ① 지금 할 일 | 오늘 할 일 ← 오늘 | `#home` |
| | 전체 일정 ← 일정 | `#schedule` |
| | 바뀐 소식 ← 보관함>바뀐 소식 | `#changelog` |
| | 캘린더에 담기 ← 일정 화면 아래 구역 | `#schedule`(구역 앵커) |
| ② 중학교 | 중학교 배정 | `#select/curriculum?v=middle` |
| | 중학교 지도 ← 학교 지도(중) | `#select/curriculum?v=map&lv=middle` |
| | 중학교 생활 | `#mid/life` |
| | 중입 일정 ← 일정 필터 | `#schedule?t=life` |
| ③ 고등학교 | 고교 종류 ← 고교 유형·전형 | `#select/curriculum?v=hs&ty=1` |
| | 고입 일정 ← 일정 필터 | `#schedule?t=hs` |
| | 학교 비교 | `#select/curriculum?v=hs` |
| | 고교 지도 ← 학교 지도 | `#select/curriculum?v=map` |
| | 학점제 쉬운 설명 ← 고교학점제 이해 | `#life/credit` |
| | 내 과목 계획 ← 내 계획표 | `#planner/plan` |
| | 학년별 할 일 ← 학년별 로드맵 | `#schedule?t=road` |
| ④ 대학 입시 | 수능과 내신 ← 수능·내신 규칙 | `#admission/system` |
| | 대학별 조건 ← 대학 요건 | `#select/curriculum?v=univ` |
| | 입시 일정 ← 일정 필터 | `#schedule?t=univ` |
| ⑤ 자료 | 바로가기 모음 | `#library` |
| | 출처 목록 / 갱신 기록 / 원본 사진 | `#library/sources` · `/status` · `/files` |

- 최상위 5개(지금 할 일·중학교·고등학교·대학 입시·자료), 2단계 최대 7개(고등학교).
- "고교 선택"·"고교 생활"처럼 단계와 기능이 섞여 있던 이름을 **내 아이의 단계** 기준으로 통일했다(마인드맵 5가지).
- **바뀌는 주소: 없음.** 모든 `#...` 해시와 `REDIRECT`(옛 주소 → 새 주소)는 그대로다. 화면 안 [입학|생활] 글자 탭과 일정 필터 탭은 메뉴 항목으로 올라가므로, 같은 주소가 메뉴에서 바로 열린다(`menu.js`의 `TABS/VAULT` → 하나의 `TREE`, `locate()`가 현재 항목을 찾는 방식은 그대로).
- 제거되는 선택 장치: 하단 탭바, 헤더 '보관함' 링크, [입학|생활] 탭, 일정 필터 탭(일정은 항목으로 분리), 중복 '학교 지도'.

## 안별 비교

### A 좌측 고정 트리
- 데스크톱: 좌측 272px 사이드바에 5개 그룹·모든 항목 상시 펼침, 현재 위치는 진하게+아래 포인트색 선. 모바일: 상단 큰 '메뉴' 버튼 → 같은 트리 서랍(`A-drawer-m.png`).
- 장점: 어디서든 전체 구조가 보여 길을 잃지 않는다. 구현이 가장 작다(트리 1개를 두 곳에 그림). 가로 폭이 넓은 PC·태블릿에 좋다.
- 단점: 처음 열었을 때 '지금 할 일' 느낌이 약하다(홈도 일반 화면). 모바일은 한 번 더 눌러야 메뉴가 보인다.

### B 마인드맵 홈
- 홈: 가운데 '스쿨 라이프' + 큰 가지 5개(눌러 펼침, 항목 높이 54px). 안쪽: '← 처음으로' + 상위 경로(breadcrumb)만, 사이드바 없음.
- 장점: 처음 보는 사람(할머니)에게 가장 쉽다 — 큰 버튼 하나씩만 고르면 된다. 마감 D-day 카드가 홈 맨 위에 있다. 안쪽 화면은 본문이 가장 넓다.
- 단점: 다른 화면으로 가려면 항상 홈을 거친다(이동 2번). 자주 오가는 사람에게는 느리다. 안쪽에서 현재 위치 외의 구조가 안 보인다.

### C 혼합 (홈=B, 안쪽=A)
- 홈은 마인드맵으로 시작하고, 안쪽 화면에서는 좌측 트리(모바일은 '메뉴' 서랍)로 바로 다른 화면에 갈 수 있다.
- 장점: 처음에는 쉽고(B), 익숙해지면 빠르다(A). 두 방식의 약점을 서로 메운다.
- 단점: 구현이 둘 다 필요하다. 홈과 안쪽의 메뉴 모습이 달라 "한 군데에서 고른다"는 원칙이 홈(큰 가지)과 안쪽(트리)로 나뉘어 보일 수 있다(같은 트리 데이터이므로 이름·순서는 동일).

## 정보성 화면 레이아웃 개선 제안 (3안 공통, 대표 화면 3개에 적용)
1. **읽기 폭 70ch**(`max-width:70ch`, 한글 약 35~40자): 본문·목록·메모는 이 폭, **표는 예외로 가로 전체**(`COMPARE-TABLE.md` 원칙 유지, 모바일은 줄바꿈으로 스크롤 없이).
2. **위계**: 제목(명조 2rem) → 큰 소제목(번호 손글씨 + 명조 1.5rem, 위에 굵은 선) → 작은 소제목(굵은 18px) → 본문(18px, 줄간격 1.75). 본문 기본 글자 18px.
3. **핵심 숫자 강조**: 화면 맨 위에 종이 조각 2~3장(192학점·2/3·40%, 2029.11.15·5등급, 11.2~6·12.31·1.4~7). 알약 배지·그라디언트 없음.
4. **'이 화면에서' 목차**: 데스크톱(1200px↑)은 오른쪽 고정 목록, 모바일은 접이식 한 줄(48px). 소제목에 앵커(`#graduate` 등).
5. **메모 상자**: 추정·주의는 점선 상자에 작은 '추정' 글씨(상태색 고정). 확정은 표시하지 않는다(CLAUDE.md 규칙).
6. 큰 터치 영역: 메뉴 항목 48px, 마인드맵 가지 76px·항목 54px, 버튼 48px.
